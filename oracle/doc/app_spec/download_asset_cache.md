# ダウンロードアセットキャッシュ

## 目的と対象

cmoc 自身が外部から取得する配布アセットを保存し、同じ資材の不要な外部取得を抑える。本書は、このダウンロードアセットキャッシュの対象、共有範囲、保存先、有効性、取得、および保持の共通契約を所有する。対象には、検索用の埋め込みモデル、runtime・ライブラリの配布物、およびそれらの準備に必要な依存物を含める。

cmoc 本体と doctor の起動に必要な事前導入の範囲は、`{{cmoc-root}}/oracle/doc/app_spec/doctor_preprocess.md` の「共通実行環境の検証」に従う。model provider の取得・cache 管理は、`{{cmoc-root}}/oracle/doc/app_spec/codex_model_provider.md` の「cmoc の責務境界」に従い、対象に含めない。

文書本文・文書埋め込み・索引、環境ごとの準備済みコンポーネント、および動作検証結果は、ダウンロードアセットキャッシュの対象に含めない。検索側の保存・共有と検証は、`{{cmoc-root}}/oracle/doc/app_spec/document_search.md` の「identity と保存先」「検索用コンポーネントの検証契約」に従う。

## 保存先と共有範囲

保存先は `/tmp/cmoc_asset_cache/<uid>/` とし、`<uid>` は cmoc を実行する OS ユーザーの数値 UID とする。同じホスト・OS ユーザーでは、repository、worktree、process、run、および cmoc の配置場所が変わっても同一アセットを再利用する。別の OS ユーザーとは共有しない。

この機能のために永続領域のキャッシュを追加したり、sandbox 設定・権限範囲を拡張したりしない。内部レイアウト、キャッシュキー、排他・公開方式、および物理コピーや参照の方式は、本書の結果を満たす範囲で実装に委ねる。

## 有効性と再利用

キャッシュヒットは、要求する版・資材の識別情報・依存関係への適合と、サイズ・ハッシュ等に基づく完全性を、ローカルで確認できた場合に限る。ファイルの存在だけでは判定しない。資材の識別に影響する OS・CPU architecture 等も区別し、要求資材と対応付けられない保存物を使用しない。

確認に必要な識別情報と完全性情報はローカルで利用できる状態にし、正本に値が指定されている場合は、そのすべてへの適合を確認する。検索用資材の正確な識別情報は、`{{cmoc-root}}/oracle/doc/app_spec/document_search.md` の「初期方式と推論の失敗」が定める委譲先に従い、本書では再定義しない。

準備に必要な資材は、キャッシュ導入前から存在するものやキャッシュに未保存のものを含め、有効なローカル資材を優先して再利用し、それがない資材だけをダウンロードする。有効なキャッシュがある資材については、再ダウンロード、更新確認、配布元への存在確認などの取得関連の外部通信を行わない。必要な依存物一式が有効に保存されている場合は、取得関連の外部通信なしでアセットを準備できることを要求する。cmoc が取得・構築に使用するツールによる依存解決やメタデータ取得の通信も、この判定に含める。

## 取得と公開

取得途中の内容や本書の有効性確認に不合格の内容を、有効なキャッシュとして公開しない。取得を完了し、有効性を確認した資材だけを、他の処理が再利用できる状態にする。

本書の共有範囲内で同一アセットを正常に並行取得する場合、不足資材の取得は全処理の合計で一度だけとし、後続処理は先行処理の完成品を再利用する。待機前に不足していたことだけを理由に、重複取得してはならない。

取得・確認・公開の失敗、取消、または異常終了でも、既存の正常な保存物と、それまでに公開できた資材を保持する。未完成の内容を完成品と誤認させず、後続処理が再利用・再取得へ進める状態にする。公開前に異常終了した資材まで、取得回数を必ず一度に限定する保証は設けない。

## 保持と回収

process 終了、run の join・abandon、または別の版の利用開始だけを理由にキャッシュを削除しない。キャッシュの回収は、これらの終了・切替処理から分離する。回収時は使用中の資材を保護し、並行利用・取得中の保存物を破損させない。

`/tmp` の永続性は保証しない。キャッシュの回収・消失によって正常な準備済みコンポーネントを壊してはならない。消失後に新たな準備で資材が不足する場合は、本書の「有効性と再利用」に従って再取得してよい。

## 診断と受入条件

再利用・取得の実績とキャッシュを使えなかった理由は、`{{cmoc-root}}/oracle/doc/app_spec/console_and_file_log.md` の「ダウンロードアセットの診断記録」に従って記録する。

受入確認では、次の条件ごとに、取得関連の通信とアセットごとの取得回数を観測する。取得回数の単位と失敗・再試行の計測は、同文書の「ダウンロードアセットの診断記録」に従う。テストの固定パス隔離は、`{{cmoc-root}}/oracle/doc/dev_rule/test_rule.md` の「基本」に従う。

| ケース | 条件 | 受入結果 |
| --- | --- | --- |
| 配置場所をまたぐ再利用 | 同じホスト・OS ユーザーのキャッシュに必要資材一式があり、準備済みコンポーネントのない別の cmoc 配置で準備する。repository・worktree・run が異なる場合も含む。 | 取得関連の通信・取得回数ともに 0 で準備できる。 |
| 通信を禁止した準備 | 準備済みコンポーネントがなく、必要な依存物一式が有効にキャッシュ済みの状態で、取得関連の外部通信を禁止して準備する。 | 通信を試みず、取得回数 0 で準備できる。 |
| 破損・別版 | 要求する一つの資材だけが破損または別版で、代わりの有効なローカル資材もない。他の必要資材は有効である。 | 不適合な内容を使用せず、要求する不足資材だけを取得する。他の有効な資材の取得回数は 0 とする。 |
| 正常な並行取得 | 同じホスト・OS ユーザーの異なる cmoc 配置の複数 process が、有効なローカル資材のない同一アセットを正常に並行取得する。 | 当該アセットの取得回数は全 process の合計で 1 とし、各 process が完成品を使用する。 |
| 途中失敗後の再実行 | 一部の資材を公開できた後、別の資材の取得・確認・公開に失敗し、再実行する。 | 公開済みの有効な資材の取得回数は 0 とし、未完成・不合格の内容を有効なキャッシュとして使用しない。 |
| 終了・版切替後の再利用 | 保存後に process 終了、run の join・abandon、別版の利用を経て、同じ資材を再び要求する。OS 等によるキャッシュの回収は起きていないものとする。 | 元の資材が保持され、取得関連の通信・取得回数ともに 0 とする。 |
| キャッシュがない正常環境 | キャッシュ導入前からの正常な準備済みコンポーネントがある状態、または準備後にキャッシュを回収・消失させた状態で、明示 doctor と通常起動・通常検索を行う。 | コンポーネントを引き続き利用でき、資材の再取得や取得関連の通信を生じさせない。 |

これらはアセット準備・再利用の受入条件であり、動作検証や doctor 全体の成功を代替しない。起動用の事前環境を満たしたうえで、使用環境での検証と通常起動・通常検索の責務は、`{{cmoc-root}}/oracle/doc/app_spec/document_search.md` の「検索用コンポーネントの検証契約」、doctor の他の成功条件は、`{{cmoc-root}}/oracle/doc/app_spec/doctor_preprocess.md` の「成功条件と保証範囲」に従って別に判定する。

# cmoc 専用文書検索

## 目的と責務

agent が必要な正本の原文へ到達するため、cmoc は日本語を含む embedding による意味検索を提供する。待ち時間と応答量を抑えるため、再ランキングは行わず、候補位置と読取り優先度を判断する材料となる類似度をまとめて返す。原文の選択・確認と判断は agent が担う。

本書は検索の意味仕様を所有する。本書と参照先で定める契約を満たす範囲で、本文の分割、cache の管理、process 構成、排他・停止などの内部方式は実装に委ねる。QMD は実行時依存に含めない。HTTP 待受、共有推論サーバー、独立した query expansion model、QMD 全機能との互換性、推論エンジンやベクトル演算の自作、および既存のキーワード検索の再実装は目的に含めない。

## 対象と信頼境界

検索対象は、call の `{{work-root}}/oracle/doc` 内の Markdown（拡張子 `.md`）のうち、oracle file と分類される文書に限る。分類・安全な列挙・性能条件は、`{{cmoc-root}}/oracle/doc/app_spec/oracle_and_realization_file_enumeration.md` の「分類結果」「traversal と事前 pruning」「Git ignore 判定の性能不変条件」に従う。

work-root は `{{cmoc-root}}/oracle/doc/app_spec/codex_exec_rule.md` の「agent call の path context」に従って接続ごとに固定し、MCP 引数から検索対象を変更させない。文書埋め込みの生成と cache への登録は、生成元 worktree で読取時に検索対象と確認した文書に限る。対象を確認できなければ失敗させる。

索引を検索へ公開する前に、再利用する文書埋め込みを含め、接続先 worktree の現在の検索対象・本文・path・位置情報との対応を確認する。再利用元の索引 identity や検索対象集合をそのまま採用してはならない。検索の提供や cache の共有によって agent のファイルアクセス権限を拡張しない。

## 検索と routing

agent が oracle doc の仕様文章を検索するときは、キーワード検索と文書検索 MCP を併用する。検索結果にもファイルアクセス制限を適用し、返された位置を手掛かりに現在の原文を読んで判断する。検索失敗と成功ゼロ件を区別し、ゼロ件だけを根拠に仕様の不存在や調査完了と判断してはならない。検索が無効な call、または検索に失敗した場合は、許可された手段で調査を続けてよい。

候補箇所は、本書の「初期方式と推論の失敗」で定める類似度の降順で採用する。採用上限は、設定 `candidate_count` と MCP 引数 `limit` の小さい方とし、`limit` の省略時は `candidate_count` を使う。件数はファイル集約・行範囲統合前の候補箇所数で数え、候補不足なら指定可能な件数の下限未満でも返す。値の範囲は本書の「設定と未確定事項」、入出力の正確な定義は「stdio MCP と失敗の公開」の委譲先に従う。

採用した候補を同一ファイルごとに集約し、work-root 相対 path、行範囲、および各行範囲の `max_similarity` を返す。同一パスは一度だけ掲載し、重複・重なりのある行範囲は統合する。`max_similarity` は、その範囲へ統合された採用候補の類似度の最大値とし、統合されなかった範囲では候補自身の値とする。本文・抜粋・見出し文は返さない。

ファイルはファイル内の `max_similarity` の最大値の降順、各ファイル内の行範囲は `max_similarity` の降順に並べる。負値も有効な類似度として扱う。候補の採用順・ファイル順・行範囲順について、同点内の順序は定めない。

類似度は同じ検索内で原文の読取り優先度を判断する材料であり、`max_similarity` は範囲全体の関連度や関連確率を保証しない。共通の必読閾値や、類似度の閾値による候補の自動除外は対象に含めない。

agent の検索・原文確認・判断規則を伝える routing policy の正確な文面は、`{{cmoc-root}}/oracle/src/oracle/prompt_builder/policy/routing.py` の `build_routing_policy` へ委譲する。完全 prompt への組込みは、`{{cmoc-root}}/oracle/src/oracle/prompt_builder/complete_prompt.py` の `build_complete_prompt` へ委譲し、検索の有効状態を実際の call と一致させる。tool の使い方は公開 tool 定義で伝え、routing policy へ重複させない。

## 同期と cache

検索要求ごとに、現在の検索対象と保存済み本文に索引を同期してから検索する。索引がなければ構築し、対象外になった箇所や変更前の本文を検索に使わない。本節は、`{{cmoc-root}}/oracle/doc/app_spec/doctor_preprocess.md` の「検索索引の同期」にも適用する。

手動の境界マーカーを要求せず、本文を切り捨てずに検索対象とする。初回構築と通常の再同期には、同じ文書埋め込みの再利用規則を適用する。本書の「identity と保存先」が定める同じ repository 内の互換な保存結果を利用し、不足する一意な文書入力片についてだけ新規生成する。

`{{run-root}}` に索引がない場合は、`{{repo-root}}` の保存済み索引・cache を再利用元として、run worktree の現在の文書へ同期する。再利用元が古くても一致する保存結果を利用し、再利用のためだけに元の索引を最新化する必要はない。再利用元が存在しない場合も、不足分を生成する。対象文書の確認・推論・必要な保存に失敗した場合は、本書の「stdio MCP と失敗の公開」に従う。

同期途中の有効な推論結果は、失敗・取消・期限超過後の再実行でも再利用できるよう保存する。同期未完了の一部や古い結果を正常な検索結果として返してはならない。正常に確認できた空集合や、全対象が空白である状態は成功ゼロ件とする。

返却時に候補位置と現在の原文の対応を確認できなければ、変更競合として失敗させる。file tree 全体の原子的 snapshot や編集 workload 全体の排他は要求しない。

診断記録は、`{{cmoc-root}}/oracle/doc/app_spec/console_and_file_log.md` の「索引同期の診断記録」に従う。

## 初期方式と推論の失敗

検索に用いる類似度は、query と文書入力片の embedding のコサイン類似度とする。値は有限の数値で値域は [-1, 1]、高いほど類似する。候補の採用と返却には同じ尺度を使い、返却件数に応じて値を再調整しない。

初期採用するコンポーネントの正確な識別情報とモデル入力条件は、`{{cmoc-root}}/oracle/src/oracle/other/document_search.py` の `INITIAL_SEARCH_MATERIALS`、`EMBEDDING_QUERY_TEMPLATE` へ委譲する。これらを repository 設定や MCP 引数で差し替えない。

モデル入力・推論結果と類似度が検索に利用できることを検証する。非数値・非有限値・値域外の類似度は推論失敗（`MODEL_FAILURE`）とする。入力の切捨て、不正な推論結果や類似度、推論処理の失敗を、成功ゼロ件や旧結果による成功へ変換しない。

## 検索用コンポーネントの検証契約

固定した識別情報と依存関係に一致し、再構築可能なコンポーネントを使用する。利用可能とする前に、通常検索で用いる実モデルの推論とベクトル演算が、使用する環境・設定で動作することを検証する。取得資材の有効性確認やキャッシュ保存の成功だけでは、動作検証済みとしない。

検証結果は確認した利用条件に限って有効とする。通常検索ではコンポーネントの準備・修復を行わず、現在の条件への適合性を確認する。不足・不一致・未検証なら失敗させて `cmoc doctor` を案内する。

準備・修復と通常起動時の検査の分担は、`{{cmoc-root}}/oracle/doc/app_spec/doctor_preprocess.md` の「検索用コンポーネントの準備と検査」に従う。

## identity と保存先

索引は、当該 worktree の現在の検索対象集合、本文と文書入力片との対応、および path・位置情報を所有する。索引 identity は worktree の実体と索引としての互換性を識別し、同じ path の別 worktree や、互換性のない索引の取り違えを防ぐ。

文書入力片は、文書からモデルへ渡す一つの入力を指す。再利用できる文書埋め込みは、入力片の内容が同一で、推論条件が互換な有効な保存結果に限る。推論条件の互換性は、文書埋め込みの値・解釈に影響する条件を基準に判定する。採用コンポーネントとモデル入力条件の正確な詳細は、本書の「初期方式と推論の失敗」の委譲先に従う。

文書埋め込みの再利用を索引 identity の一致に依存させない。worktree・branch・commit・path の変更だけでは再生成せず、索引形式や分割方式が変わった場合も、同一の入力片と互換な推論条件を持つ保存結果を再利用する。

以下は索引・文書埋め込み・準備済みコンポーネントの保存先とする。構築に使う取得資材は、`{{cmoc-root}}/oracle/doc/app_spec/download_asset_cache.md` の「目的と対象」「保存先と共有範囲」「有効性と再利用」に従って別に管理する。

| 管理物 | 保存先 | 使用・共有範囲 |
| --- | --- | --- |
| worktree ごとの索引 | `{{work-root}}/.cmoc/gu/document_search/` | 当該 worktree の検索に使用する。 |
| 文書埋め込みの cache | `{{repo-root}}/.cmoc/gu/document_search/` | 同じ repository の worktree・process・run 間で再利用する。別 repository とは共有しない。 |
| 準備済みの共有コンポーネントとその管理情報 | `{{cmoc-root}}/.cmoc/gu/document_search/` | 同じ cmoc installation の repository・worktree・process 間で共有する。 |

これらは再生成可能な cmoc 管理物であり、非追跡保証は `{{cmoc-root}}/oracle/doc/app_spec/doctor_preprocess.md` の「管理領域の非追跡保証」に従う。root が同じ path を指す場合も、管理物ごとの共有範囲と保持・回収の責務を区別する。物理コピーや cache の参照方法、内部の保存形式、互換性を表す具体的なキーは実装に委ねる。

文書埋め込みの cache は、文書の変更・削除や run の join・abandon によって索引からの参照がなくなったことだけを理由に、互換な保存結果を削除しない。後続 run でも再利用できるよう repository 単位で保持し、cache の回収は worktree の終了処理から分離する。

互換性を失った管理物は検索へ公開せず、前段の保持条件を満たし、使用中の資源を保護しながら不要な管理物を回収する。worktree 終了時は、その処理を停止して当該 worktree 固有の管理物を削除し、repository 単位の cache、共有コンポーネント、および他の worktree の索引を保持する。異常終了後も安全に復旧できるようにする。

## 排他、期限、終了

同じ cmoc installation の検索・同期・doctor 検証で同時に常駐するモデルは、合計一つまでとする。索引、文書埋め込みの cache、およびコンポーネントの並行利用・更新・回収で、資源の破損、準備途中の公開、停止不能を起こさない。準備に失敗しても既存の正常なコンポーネントを保持する。

ダウンロードアセットの並行取得と保持・回収は、`{{cmoc-root}}/oracle/doc/app_spec/download_asset_cache.md` の「取得と公開」「保持と回収」に従う。

正常な並行同期では、同じ repository 内の同一入力片・互換条件で不足している文書埋め込みを、全体で一度だけ生成する。後続処理は先行処理の有効な保存結果を再利用し、待機前に不足していたことだけを理由に重複生成しない。推論結果を保存する前の異常終了まで含めて、生成を必ず一度に限定する保証は設けない。

MCP 検索要求では、進捗のある同期には時間を与えつつ、待機・停滞と要求全体を有限時間で打ち切る。期限は日時の変更に左右されずに判定する。期限設定の意味は次のとおりとし、値・型・制約は本書の「設定と未確定事項」の委譲先に従う。

| 設定 field | 対象とする時間 |
| --- | --- |
| `resource_wait_timeout_seconds` | 要求内の累積資源待ち時間。 |
| `sync_no_progress_timeout_seconds` | 各自動同期で実際の処理完了が進まない時間。資源待ちは除く。 |
| `post_sync_search_timeout_seconds` | 初回同期完了から検索の完了・打切りを判断するまで。待機と再同期も含む。 |
| `search_request_timeout_seconds` | 要求受付から停止処理へ移るまでの全体上限。進捗や再同期で延長しない。 |
| `request_timeout_seconds` | コンポーネント検証の推論要求。 |
| `startup_timeout_seconds`、`shutdown_grace_seconds` | 推論処理の起動期限と、強制停止前の終了猶予。 |

処理中の通知や同じ処理の繰返しだけを進捗として期限を延ばさない。MCP 検索要求で適用中の期限に達したら処理を打ち切り、期限超過として返す。取消は別の失敗として識別する。外側の tool 期限との関係は、`{{cmoc-root}}/oracle/doc/app_spec/codex_exec_rule.md` の「文書検索 MCP」に従う。

doctor preprocess の索引同期には、初回構築や大量の差分を処理するため、資源待ちや推論処理の起動を含めてタイムアウトを設定しない。コンポーネントの検証期限は索引同期へ適用しない。

失敗・取消・期限超過・接続終了では、処理を有限時間で停止・回収し、後続処理が資源を安全に再利用できる状態にする。親の異常終了時も、子 process やモデルを孤立させない。これは doctor の処理にも適用する。

## stdio MCP と失敗の公開

公開 tool は検索だけとし、query と任意の候補数上限 `limit` を受け取る。`tools/list` の公開定義だけで、補足 prompt や仕様文書を読まずに利用し、類似度の意味と読取り優先度への使い方を判断できるようにする。正確な詳細は、`{{cmoc-root}}/oracle/src/oracle/other/document_search.py` の次の定義へ委譲する。

| 委譲先 | 所有する詳細 |
| --- | --- |
| `SEARCH_MCP_SERVER`、`SEARCH_TOOL_NAME`、`SearchErrorCode` | 公開名と失敗 code。 |
| `build_search_tool_description` | 機能・検索対象・接続の work-root、および類似度の利用目的と判断上の限界を伝える説明文。 |
| `SEARCH_TOOL_INPUT_SCHEMA` | 引数の構造・制約・意味と省略時の扱い。 |
| `SEARCH_TOOL_OUTPUT_SCHEMA` | 成功・成功ゼロ件・検索失敗の構造、field・型・数値制約、および値と順序の説明。 |

検索結果と検索中の失敗は schema に適合する `structuredContent` と、同じ値の JSON text で返す。検索中の失敗には `isError=true`、code、理由と案内可能な対処方法を付ける。root・列挙・読取、同期・保存、変更競合、未準備、コンポーネント不一致、推論、期限超過、取消を区別する。引数不正は JSON-RPC の入力エラーとして扱う。

行範囲の要素構造は出力形式の互換性に関わるため、公開 schema、返却処理、および結果を読む側の形式を整合させる。

公開定義へ agent の判断に不要な内部説明を含めない。stdio の stdout は MCP protocol 専用とする。接続の起動・固定 context・終了は、`{{cmoc-root}}/oracle/doc/app_spec/codex_exec_rule.md` の「文書検索 MCP」に従う。

## 設定と未確定事項

tuning 設定の field・型・数値制約・項目間制約・暫定既定値は、`{{cmoc-root}}/oracle/src/oracle/other/cmoc_config.py` の `DocumentSearchConfig`、新規生成時の検索設定は同ファイルの `CmocConfig.document_search` へ委譲する。`candidate_count` と `limit` に共通する指定範囲は、`{{cmoc-root}}/oracle/src/oracle/other/document_search.py` の `SEARCH_CANDIDATE_COUNT_MIN` と `SEARCH_CANDIDATE_COUNT_MAX` へ委譲する。検索設定と call ごとの有効化は区別する。

設定の保存・検証・不足補完は、`{{cmoc-root}}/oracle/doc/app_spec/doctor_preprocess.md` の「検索設定の検証と補完」に従う。検索・索引同期でも使用する保存済み設定を検証し、起動後の不足や不正を暗黙に補完せず、検索未準備として理由と修復方法を返す。

暫定既定値は利用開始のための値であり、性能保証ではない。全体負荷での時間・メモリ・検索品質の測定と tuning は後続の調整事項とし、数値の合格基準は定めない。

## 製品受入条件

本書と委譲先の契約を、正常系・境界値・失敗・編集競合・並行利用・異常終了からの復旧について検証する。正規の cmoc 起動環境と採用する Codex CLI で、tool の公開・検索・期限・取消・接続終了の連携を確認する。doctor による新環境での準備と再実行、通常起動の未準備検出も対象とする。

検索結果について、次の条件を確認する。

| 観点 | 確認内容 |
| --- | --- |
| 類似度と採用順位 | 既知の embedding から求めたコサイン類似度の降順と候補の採用順位が一致する。同じ query・文書入力片の組では、返却件数を変えても値が変わらない。 |
| 集約・統合と順序 | 同一パスが一度だけ現れ、重複・重なりを統合した範囲には採用候補の最大値、未統合の範囲には候補自身の値が返る。ファイルと各ファイル内の行範囲は「検索と routing」の降順に従う。 |
| 負値・同点と境界値 | 負値・0・値域の両端を有効として扱い、同点でも降順の契約と件数上限を満たす。同点内の特定順序は合否条件にしない。 |
| 件数上限 | `limit` の省略時・指定時と候補不足を含め、集約・統合前の採用候補数に上限を適用する。集約・統合後の件数が減っても、その分を追加採用して上限を超えない。 |
| 成功ゼロ件と失敗 | 正常に確認できた空集合・全対象が空白の状態を成功ゼロ件とし、検索失敗と区別する。非数値・非有限値・値域外の類似度は `MODEL_FAILURE` とし、成功結果を返さない。 |
| 公開出力 | 成功・成功ゼロ件・失敗が公開 schema に適合し、`structuredContent` と JSON text が同じ値を表す。返却処理と結果の利用側が schema の行範囲 object と行番号の制約に対応する。 |
| 公開利用説明 | 公開 tool 定義だけで、類似度の尺度・統合時の意味・順序・利用目的と限界を解釈でき、現在の原文を読んで判断する責務が分かる。 |

検索用のモデル・runtime・ライブラリと準備に必要な依存物について、`{{cmoc-root}}/oracle/doc/app_spec/download_asset_cache.md` の「診断と受入条件」を満たすことを確認する。そこでの取得関連の通信・取得回数と、本書の動作検証・文書埋め込み生成数は別に判定する。

文書埋め込みの再利用は、初回構築と通常の再同期を通じて次の生成数で確認する。生成数は文書埋め込みだけを対象とし、query やコンポーネント検証の推論を含めない。計測単位と生成・再利用の内訳は、`{{cmoc-root}}/oracle/doc/app_spec/console_and_file_log.md` の「索引同期の診断記録」に従う。

| ケース | 同じ repository 内での条件 | 文書埋め込みの新規生成数 |
| --- | --- | --- |
| (a) 新しい run | 同じ文書内容・推論条件の全入力片について互換な保存結果がある状態で、索引のない新しい run を同期する。再利用元の索引が古い場合も含む。 | 0 |
| (b) 部分編集 | 文書を部分編集して同期する。同一の未保存入力片が複数箇所に現れる場合も含む。 | 互換な保存結果がない一意な入力片の数だけ |
| (c) 移動・重複 | 互換な保存結果のある文書を、内容・推論条件を変えずに移動・rename する、または同一内容を別 path に追加する。 | 0 |
| (d) 並行同期 | 複数 worktree が同じ一つの未保存入力片を、互換な推論条件で正常に並行処理する。 | 全 worktree の合計で 1 |
| (e) run 終了後 | run で生成・保存した後、その run を join または abandon で削除し、別 run が保持済みの同じ入力片を互換な推論条件で使う。 | 0 |

併せて、索引形式・分割方式の変更後も同一入力片の互換な保存結果を再利用すること、失敗・取消・期限超過前に保存できた有効な結果を再利用すること、および再利用元だけにある対象外の文書・古い本文・位置情報を検索へ採用しないことを確認する。

過去の PoC の結果を製品での検証完了や性能保証とは扱わず、未検証の環境や条件は区別する。

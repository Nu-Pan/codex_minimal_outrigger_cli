# `cmoc` における `{{work-root}}` 上の `INDEX.md` の扱い

## 概要

`INDEX.md` は、AI agent が読むべき本文を選ぶための routing 情報である。cmoc は、本書の「`INDEX.md` 配置対象ディレクトリ」に従って `{{work-root}}` 配下へ配置し、自動でインデクシングする。そのため、人間が `INDEX.md` を書く必要はない。

## `INDEX.md` 配置対象ディレクトリ

- `{{work-root}}` 配下のディレクトリを再帰的に列挙する
- 以下のディレクトリは配置対象から除外する
    - `.` から始まるディレクトリ
    - `.gitignore` の対象
    - `{{work-root}}/memo`

## 目次作成対象ファイル・ディレクトリ

- `INDEX.md` と同階層のファイル・ディレクトリを列挙する
- 以下のファイル・ディレクトリは目次作成対象から除外する
    - `.` から始まるファイル・ディレクトリ
    - `.gitignore` の対象
    - `{{work-root}}/memo`
    - `INDEX.md`
    - バイナリファイル

## `INDEX.md` のフォーマット

ファイル・ディレクトリ 1 件ごとに、以下のフォーマットで「目次情報」を用意する。各節の本文は箇条書きとする。

```markdown
# `{{ファイル・ディレクトリ名}}`

## Summary

{{ルーティング先ファイル・ディレクトリの説明}}

## Read this when

{{どんな作業・質問・変更のときに、このファイル・ディレクトリを読むべきか}}

## Do not read this when

{{逆に、このファイル・ディレクトリを読まなくて良い・読んではいけないケース}}

## hash

{{この目次情報を生成するにあたって参照したファイル・ディレクトリとそのハッシュ}}
```

各節には、次の内容を記載する。

| 節 | 内容 |
|---|---|
| `Summary` | ファイル・ディレクトリに何が書いてあるか、何が入っているかを説明する。 |
| `Read this when` | AI が対象を読むべき条件を明示する。 |
| `Do not read this when` | AI が「関連しそう」という理由だけで過剰に読まないよう、対象を読む必要がない条件や、読んではいけない条件を書く。 |
| `hash` | 目次情報の生成で参照した対象の SHA-256 ハッシュ値を書く。計算方法は対象の種類に応じて次のように定める。 |

- ファイルの場合は、その内容である文字列から SHA-256 を計算する。
- ディレクトリの場合は、直下の目次作成対象ファイル・ディレクトリをリポジトリ相対パスの辞書順で安定ソートする。各エントリについて `type + '\0' + relative_path + '\0' + content_hash + '\n'` を連結した UTF-8 文字列から SHA-256 を計算する。

## 目次情報の意味要件

目次情報は、対象本文の代替となる詳細説明にしてはならない。

`Summary`、`Read this when`、および `Do not read this when` は、次の要件を満たす。

- 人間が読む自然言語部分は原則として日本語とする。識別子、path、command、hash、および引用は元の表記を維持してよい。
- 目次情報は対象の現在内容を根拠とし、対象外の責務または将来の用途を推測で追加しない。
- 対象が担う責務と、同階層の別対象ではなくその対象へ進む条件を示す。
- 関連しそうという理由だけで対象へ進ませる広すぎる条件を避ける。
- 対象を読まなくてよい境界、またはより直接的な参照先がある場合の境界を示す。
- ファイル名、ディレクトリ名、hash、出力形式、または Structured Output schema の項目などは、cmoc が機械的に補う情報である。これらを自然言語へ混ぜると routing 判断に必要な意味情報が薄まるため、routing 用の意味情報へ混ぜない。

## `INDEX.md` による routing

以下は通常作業で参照先を選ぶための規則とし、目次情報の生成 call には適用しない。

- agent は、作業対象に近い階層の `INDEX.md` から必要な本文を選ぶ。対象領域を推定できない場合は `{{work-root}}/INDEX.md` を起点とする。
- `Read this when` と `Do not read this when` を選択に使用し、関連候補を総当たりで読む前に対象を絞る。
- 意味または最新状態は、選択した本文を根拠に判断する。`INDEX.md` と本文が食い違う場合も、本文を優先する。

## インデクシングの仕様

### 処理対象

1. 配置対象ディレクトリは前述のルールで機械的に列挙する
2. 列挙されたディレクトリを「深い方から」順番に処理する
3. インデクシングによって発生した git 未コミット差分を自動コミットする
    - インデクシングの呼び出し 1 回につき、1 つのコミットにまとめること
    - コミット対象は `INDEX.md` の差分だけとし、インデクシング開始時点の同ファイルの既存差分も含めてよい
    - 既存差分が存在した場合も処理は続行する

### ディレクトリ１つごとの処理

- `INDEX.md` が存在しなければ新規に作成する
- `INDEX.md` 内の目次情報に不備がないか確認する
    - 本書の「目次作成対象ファイル・ディレクトリ」に含まれる対象の目次情報がなければ、新規に作成する
    - 目次作成対象に含まれないファイル・ディレクトリの目次情報は削除する
    - 記録されているハッシュ値と実際のハッシュ値が一致しない場合は、目次情報を削除して再生成する

### 目次情報の生成方法

- 目次情報の生成対象 1 件ごとに、独立した agent call を行う
- agent には対象パスを渡し、本文を prompt へ埋め込まない。agent は、ファイルならその本文を、ディレクトリならその現在内容を説明する実ファイルの本文を読む。理解に必要な関連本文も参照してよい。
- 生成 call では、子ディレクトリを含む既存の `INDEX.md` を読まない。
- agent call は本書の「目次情報の意味要件」に従う。正確な prompt part、文面、workload 固有の起動パラメータ、およびその選択理由は、`{{cmoc-root}}/oracle/src/oracle/acp_builder/indexing/index_entry.py` の `build_indexing_index_entry_parameter` へ委譲する
- 「ファイル・ディレクトリ名」「ハッシュ値」などの機械的に処理可能な部分は cmoc が責任を持つ

## 目次情報生成の並列実行

目次情報生成のための `codex exec` 呼び出しは、可能な限り並列に実行する。ただし、本書の「処理対象」が定める、深いディレクトリから処理する順序を守る。並列化してよい組み合わせは次のとおりとする。

- 同じ `INDEX.md` 内のエントリ同士
- 祖先・子孫の関係にない `INDEX.md` 同士

## インデクシングの実行条件・タイミング

- agent call 共通実行経路による自動 preflight は、`AgentCallParameter.run_indexing_preflight == True` の場合だけ、その論理 agent call の初回 Codex call の直前に行う
- `cmoc oracle edit` が呼び出し元として管理する indexing の順序と回数は、`{{cmoc-root}}/oracle/doc/app_spec/sub_command/oracle_edit.md` の「実行順序」を正本とする
- ユーザーによる明示実行は、`{{cmoc-root}}/oracle/doc/app_spec/sub_command/indexing.md` の「実行手順」に従う

## `INDEX.md` が最新に保たれている状態でメンテナンス処理が実行されたら

機械的チェックで最新状態であることを確認し、Codex CLI による目次生成は一切実行しない。

# `doc`

## Summary
- 人間が所有する正本仕様文書群の入口で、cmoc の動作要件、開発規約、branch・commit・worktree の共通概念、設計判断の記録を含む。
- 製品仕様は、共通の動作契約と個々のサブコマンドの条件・手順・失敗時の扱いを定める。
- 開発規約は実装構成、コーディング方針、環境準備、検査の実行方法を扱う。
- branch モデルは session と run の branch・commit・worktree の役割と関係を定める。
- 採用しなかった案の記録は過去の判断理由と現行仕様への参照を示す背景資料であり、現行動作の正本ではない。

## Read this when
- cmoc の動作要件、責務境界、ファイル分類やアクセス、保存状態、コマンドの lifecycle、失敗時の扱いを決める・確認するとき。
- 複数の仕様にまたがる用語や責務、優先関係を整理するとき、または読むべき下位仕様を特定できないとき。
- session や run の branch・commit・worktree の関係が作業に関わるとき。
- 実装方針、開発環境、品質検査の選択を確認するとき。
- 現行設計の背景や、過去に検討された案との境界を確認するとき。

## Do not read this when
- 対象のコマンドや論点に対応する正本仕様が特定できており、単一の要件だけを確認すればよいときは、その仕様へ直接進む。
- 正確な prompt 文面、構造化出力の schema、アルゴリズムや選択値など、別の正本へ委譲された細部だけが必要なときは、その委譲先を直接確認する。
- 意味上の要求が確認済みで、必要なのが実装やテストの現在の挙動だけであるときは、該当するコードやテストへ直接進む。

## Read this when
- 共通 prompt の構成や、操作ごとの agent call が受け取る指示・パラメータの実装を調査または変更するとき。
- パス、設定、文書検索、文書参照、構造化文書のモデルや、handoff・フィードバック処理の実装を追うとき。

## Do not read this when

## cmoc oracle refactor を追加する

- oracle file の品質は、それをレビューする人間の認知負荷低減するために重要
- そのためには $japanese-writing-skill みたいな品質系スキルを全てのファイルにあまねく適用できれば良い
- GPT-5.6 Sol ultra みたいなサブエージェントに任せるという手だと、子エージェントに注入するプロンプトを cmoc のルールで握る事が出来ない
- `cmoc realization refactor` みたいにファイル単位での改善を行うサブコマンドが必要
- 品質基準がスキルでフォローされる事を前提としてしまうが、これは cmoc --> スキルの依存関係なので避けたい
- 仕様の意味を壊さない範囲で、具体性があって検証しやすい話だけをリファクタの対象とする

## マルチエージェント実行前提への移行

- 単一の worktree 上で書き込みを伴うエージェントが複数同時に動くと、コンディションレースが発生する
- この状況は codex 側の機能でマルチエージェント実行をした場合に容易く発生する
- cmoc から codfex を起動する場合、原則として git branch, worktree を隔離して実行すべきだろう
- できれば codex 内で生成されたサブエージェントも隔離実行の仕組みに乗せたい
- 最悪の場合でも、異なるセッション間の通信手段だけ用意する感じか
- メイン worktree の未コミット差分を隔離時に転送するとかの仕組みは必要だろう

- cmoc feedback report を再編して「テスト・検証の全通過」を組み入れるのが丸い気はする

# Structured Outputs のスキーマをオフラインで検証する

OpenAI Structured Outputs 用のスキーマを、このスキルに付属する検証コマンド（配布 CLI）でオフライン検証する。JSON Schema 一般や生成済みデータの適合性検証には使わない。利用者が指定したファイルを優先し、指定がなければスキーマを使うコードや設定から対象ファイルを特定する。

配布 CLI は、バージョンごとに固定した検証規則（プロファイル）に従い、キーワードが許可されているか、スキーマの規模が上限内かを検査する。ただし、プロファイルに適合しても、リモートサービスがスキーマを受理するとは限らない。

## 配布 CLI を実行する

この `SKILL.md` があるディレクトリを `{{skill-root}}` とし、次のコマンドを対象ファイルごとに実行する。このスキルによるプロファイルへの適合性の検査はオフラインで行い、その検査のために API や Codex CLI を呼び出さない。

```bash
python3 {{skill-root}}/scripts/validate_schema.py \
  --profile openai-structured-outputs-2026-08 \
  path/to/schema.json
```

診断結果をプログラムで処理する場合は `--format json` を追加する。検証の結果は、終了コードから判断する。

| 終了コード | 結果 |
| --- | --- |
| `0` | プロファイルに適合した。 |
| `1` | 入力やスキーマの違反を検出した。全診断を確認する。 |
| `2` | 引数、読み込み、内部処理などの問題で検証できなかった。 |

このプロファイルでは、未知のキーワードもエラーになる。そのため、一般の JSON Schema 検証ツールによる検査が成功しても、配布 CLI の検証を代用したことにはならない。

## 診断を解消して報告する

修正の可否と範囲は、元の依頼とセッションで認められた作業範囲から判断する。アプリやスキーマの作成・変更を任されている場合は、その作業に必要な不整合の解消も含める。一方、レビューだけの依頼ではファイルを変更しない。

後方互換性は原則保持しない。明示要件がある場合だけ保つ。明示要件は、利用者の指示、AGENTS.md、正本仕様から確認する。変更後の契約を満たす単純なスキーマへ整理し、未要求の旧形式や旧項目を受理するための分岐を追加・保持しない。変更で不要になった関連定義や説明も整理する。

修正では、アプリの正本仕様からスキーマが満たすべき契約を確認し、診断結果からプロファイルへの適合性を確かめる。そのうえで、診断が示す箇所と関連する定義を一緒に読み、契約を保って不整合を解消する。テスト用のスキーマでは正常入力か拒否を確認する入力かを確かめ、意図した違反を消さない。

修正後は同じプロファイルで再検証する。また、併用する規則が同じスキーマの検査を求める場合は、結果を共用する。

報告では、検証したファイルとプロファイルを示し、適合・違反・検証不能のどの結果になったかを伝える。違反が残る場合は、診断コードと JSON Pointer を示し、違反の原因と箇所をたどれるようにする。
